# ClickIT Solutions — Website Demo (Homepage)

A single-page demo of the proposed new ClickIT Solutions website, built to show the client the
direction before the full project is quoted.

**Stack:** Astro 7 · TypeScript · Tailwind CSS 4 · Vercel-ready static output

## Run it

```bash
npm install
npm run dev                # http://localhost:4321
npm run build              # static output in dist/
npm run preview            # serve the production build locally
npm run verify             # SEO / a11y / payload checks against the build

# Browser-driven checks (headless Chrome, no test framework needed).
# Start `npm run preview -- --port 4342` first, then:
npm run check:runtime      # overflow, console errors, mobile menu, form submit
npm run check:contrast     # WCAG AA contrast for every visible text node
npm run check:backgrounds  # asserts the white-page / gray-card surface rule
npm run check              # build + verify + runtime + contrast
```

### Design system

Two surface tokens drive the whole page, both defined in `src/styles/global.css`:

| Token | Value | Applied to |
| --- | --- | --- |
| `--color-surface-page` | `#ffffff` | `body`, every `<section>`, header, footer, 404 |
| `--color-surface-card` | `#f3f4f6` (`gray-100`) | every card, tile, panel and input-adjacent surface |

Dark ink (`--color-ink-950` … `--color-ink-100`) is used only for text, primary buttons, the logo
mark, and the illustrative product mockup inside the hero — never as a section background.
`npm run check:runtime` asserts every `<section>` computes to exactly `rgb(255, 255, 255)`.

## SEO built in from the start

- Single `<h1>`, clean `h2`/`h3` hierarchy, no skipped levels (verified by `npm run verify`)
- Unique title + meta description, canonical URL, robots directives
- Open Graph + Twitter card metadata with a real 1200×630 image
- JSON-LD: `Organization` / `ProfessionalService`, `WebSite`, `WebPage`, `LocalBusiness`, `Service`
  with an `OfferCatalog` of all 9 services, `FAQPage`, `BreadcrumbList`
- `sitemap-index.xml` generated by `@astrojs/sitemap`, `robots.txt` with sitemap reference
- Semantic HTML, skip link, labelled form fields, `aria-*` states, `prefers-reduced-motion` support
- Fully static HTML — every page is server-rendered markup, no client-side hydration

## Conversion tracking (env-driven, nothing hardcoded)

| Env var | Purpose |
| --- | --- |
| `PUBLIC_GA_MEASUREMENT_ID` | GA4 |
| `PUBLIC_GTM_ID` | Google Tag Manager (takes priority over GA4 direct loading) |
| `PUBLIC_GADS_ID` | Google Ads conversion tag |
| `PUBLIC_FORM_ENDPOINT` | Form submission endpoint (CRM / form service) |
| `PUBLIC_PHONE_DISPLAY` / `PUBLIC_PHONE_E164` | Phone CTA |
| `PUBLIC_WHATSAPP_NUMBER` / `PUBLIC_WA_MESSAGE` | WhatsApp CTA |
| `PUBLIC_SITE_URL` | Canonical + sitemap origin |

Copy `.env.example` to `.env` to configure. With no values set, no analytics scripts load at all
(no third-party requests, no Lighthouse penalty).

Tracked events pushed to `window.dataLayer`:

```
page_view            lead_form_start        lead_form_submit
cta_whatsapp_click   lead_form_success      nav_click
cta_phone_click      lead_form_error        case_study_click
cta_consultation_click
```

Attach a Google Ads conversion to `lead_form_success`.

## Form

`sections/Contact.astro` — fields: full name*, company, phone*, email*, service required*,
project description, estimated budget (optional), preferred contact method. Client-side validation
with inline errors, a form-level error banner, a honeypot, and a success state. Currently in
**demo mode** (validates and confirms client-side) until `PUBLIC_FORM_ENDPOINT` is set.

## Performance

Measured on the production build:

| Asset | Size |
| --- | --- |
| HTML | 26.4 KB gzip |
| CSS | 11.8 KB gzip |
| JS | 0 KB (all inlined, none deferred to a framework runtime) |
| Fonts | 2 variable subsets preloaded, self-hosted, no Google Fonts request |

No framework runtime is shipped. Icons are inline SVG, imagery is CSS-drawn, fonts are self-hosted
and preloaded. Total transfer for a first visit is roughly 115 KB.

## What is intentionally not built

This is a homepage demo only. The following are scoped but not yet created — the content
architecture and data model for them already exist in `src/data/`:

- Service detail pages (`/services/[slug]` — the 9 slugs are defined in `src/data/services.ts`)
- Industry pages, Case Study detail pages, Portfolio index, Insights/blog + article pages
- About, Contact standalone pages, Privacy Policy, Terms
- CMS integration for blog / case studies / services / FAQs

## Content honesty

No testimonials, client names or results are invented. Real projects used: Jipangishe, QX Carwash,
Carlink Tanzania. Where a number would normally go (case study results, proof stats), the page
either says so explicitly or omits it.

**Known demo placeholder — must be resolved before launch:** the hero product mockup renders
illustrative interface figures (`TZS 48.2M`, `+18%`, `312`, `92%`, "Receipt auto-sent · 2s") purely
to show what an operations dashboard looks like. They are not ClickIT or client results and are not
labelled as such in the UI. Either replace them with real, approved figures or remove the mockup.
The same applies to the proof band entries "School systems" and "Fleet platforms", which are
category labels rather than named clients.

Any additional project can be added to `src/data/content.ts` and it will render in the existing grid
with no layout change.
